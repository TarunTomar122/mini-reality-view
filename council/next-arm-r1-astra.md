# Astra · next arm after vpriv

**(1) Train one arm with memory from the last DDIM call, conditional on a signed vpriv miss and the probe below.** Keep frozen A@20k, vpriv’s recorded temporal initialization and draws, both clips private, 2 × 16 ticks, K=4, ε-MSE on ticks 1–15, and r1’s optimizer and camera dropout.

Let t* be the actual last timestep in the 25-call schedule. During training, make one extra batched frozen-A forward at t* on the key latents noised to t* with private draws and the same camera-dropout mask. Save detached spatial features before each temporal block. Apply trainable K/V projections to those features. Each noisy query at the usual uniform clip timestep reads its own noisy self and only the preceding four available feature rows. Exclude t* from query draws because that call only writes memory in deployment. This amends r1’s same-step memory and clean-past restriction. Per-token noise levels have precedent in [Diffusion Forcing](https://arxiv.org/abs/2407.01392).

At rollout keep camera-only conditioning, signed ρ=0.95 noise, DDIM-25, η=0 and CFG 2. Calls 1–24 read one ring per block, with separate CFG rows. Call 25 runs with temporal deltas off and stages K/V from its spatial features. Publish once after the tick, evict beyond four, clear on hard breaks and retain across camera swaps. No extra inference forward. This tests whether the already-computed low-noise features carry usable scene history.

Cost per update is one extra frozen forward over 32 frames, with no backward through that forward. Budget from a 100-update timing and peak-memory check on the existing slice (vpriv reference 0.50 s/update). Persistent rollout K/V falls from 25 rings to one per layer. Recheck T1–T7, especially clip/stream agreement through eviction and first-tick equality after reset.

**(2) Probe generated history before committing the slice.** Run the same frozen-weight test separately at vpriv 8k and 12k. Use the eight fixed five-tick dev clips, seed 0, one draw, recipient t=300 and 700. Generate the four prefix ticks with the proposed rollout. Hold the recipient’s key, cameras and ε fixed, using the prefix’s shared seed component. Score recipient ε-MSE with true final-call K/V, a different drive’s final-call K/V generated with the same noise tensors, and blocks off. Also score true teacher-forced t* history to expose the training-to-rollout gap. Generated-history exposure bias is documented in [Self Forcing](https://arxiv.org/abs/2506.08009).

Budget per checkpoint is at most 64 generated frames including donors (~3.6 min at the quoted base timing), plus short recipient forwards and scoring. Cap each probe at 60 GPU-minutes. Average paired clip differences within drive, then across drives. Keep the arm only if true generated history beats both off and donor at t=300 at both checkpoints and is no worse than off at t=700 at both. Otherwise release the slot. An incomplete probe gives no launch decision.

**(3) Keep the signed gate and A1 timing.** Require both eligible reductions vs signed A strictly above 9.4%, car F1 ≥ A−0.03 and late gap vs matched cold ≤ +0.03. Confirm N1 and extend its pre-exam ghost/road review to this arm. If vpriv passes, its exam takes precedence subject to N1. Report entry/exit examples from matched clips to distinguish delayed appearance from stale cars. Keep latency claims tied to measured camera-to-display p50/p95 and sustained fps.

**(4) Narrow the causal claim.** Changing past noise reversed teacher-forced recipient MSE at t=300. That experiment did not measure generated-history ID, W or ghosts. The last UNet call sees a still-noisy latent before the scheduler update, and generated prefixes can preserve shared-seed artifacts. At 2k, W was 2.3% worse than A and the F1 difference interval reached −0.067. Persistent detections alone cannot identify stale cars. Comparisons with vlive also include an initialization change.

PROPOSAL: If vpriv misses, train the single final-call memory arm only when genuine generated prefixes pass the paired 8k and 12k probes.
