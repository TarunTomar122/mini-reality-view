# Causal video, round 2 (Fable, s2, 27 Nov)
**Merged pick: same-noise-level training (mine) + Astra's 4-tick window, age bias and test list. One design, no two-arm ablation.**
## Per point
1. **Window: concede, K = 4** (self + the 4 ticks before). Stacked over 16 blocks the reach stays long; the cache drops from 4.0 to 2.3 GB per stream (fits a 2080 Ti); a departed car has fewer places to linger; ID / W are tick-to-tick measures anyway.
2. **Noise: hold, one level for the whole clip.** (a) Our record: a near-clean previous frame beside a noisy current one copied under 3 recipes. Astra's prefix t = 50 / 100 / 200 is noise std ~0.22 / 0.32 / 0.50 in our `s` units (my arithmetic on the SD schedule): the range arm C and lever 2 (s 0.3-0.7 + 40% dropout) already trained on, with true keys in training and own frames live (arm C's gap). The stale swap shifts history 0.1 s; it does not remove "the past is nearly the answer". (b) 2609.22283, re-fetched today: total clean 84.45 / same-level 85.24 / progressive 85.60; dynamic degree 77.8 / 84.7 / 86.1 (appendix, read via a page summary). (c) Live use = joint causal denoising run tick by tick, so training and live match and there is an exact unit test (T4).
   **Ablation: no.** Copying shows late (arm C drift +0.006 at 5k, +0.059 at 10k; lever 2 +0.014 at 10k, +0.039 at 15k); at 2k the copier looks smoother and wins. Tripwire = the probe below. If smoothness misses: progressive history, never a clean past.
3. **Attention: mine, with Astra's age bias replacing my RoPE** (less code to check). Drop null slot, write pass, stale swap: they exist to distrust a clean past and there is none. I give up two real advantages of Astra's: a ~100x smaller cache, exact A control.
4. **Cache: per DDIM step.** Slot (step j of 25, block l of 16), cond / uncond as separate batch rows, holding the block's normed input for the last 4 ticks (fp16). 0 extra UNet passes vs A (the write pass goes). Per-frame caching cannot work at same level.
5. **New: "off = A's renders" has a hole.** A's signed renders reuse ONE noise tensor at every tick (temporal_rollout.py:96); the held video code uses half shared / half private noise, and fresh noise alone costs ID +54% / W +37%. Training on fully shared noise is no fix: x_t(i) - x_t(j) = sqrt(abar) (x0(i) - x0(j)) shows true motion noise-free at every level, and live it starts at 0 = "nothing moved" = freeze. So one shared share rho < 1, the SAME in trainer and rollout. Smoothness / F1 comparator stays A's signed renders (harder for us); late-gap cold = `--off` at the same rho, rendered once (it does not depend on the checkpoint).
